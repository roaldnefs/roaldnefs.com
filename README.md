## How it works
The site is plain static HTML generated by [Hugo](https://gohugo.io/). It has no theme dependency, no Node build step and no backend. Everything lives in this repository.

| Path | Purpose |
| --- | --- |
| `content/` | Markdown pages and blog posts (`content/posts/`). Front matter sets title, date, tags and `featured`. |
| `layouts/` | The custom theme: page templates, partials (header, footer, author box, company cards) and shortcodes (`callout`, `toc`, `companies`). |
| `assets/css/main.css` | A single plain CSS file with light and dark themes, minified and fingerprinted by Hugo Pipes. |
| `data/companies.yaml` | Warpnet and Enlite details, used on the homepage, the About page and the footer. |
| `static/` | Files copied as-is: images, slides, favicons, `CNAME` and `robots.txt`. |
| `hugo.yaml` | Site configuration: menu, permalinks, syntax highlighting and author details. |

JavaScript is kept to a minimum and inlined: a theme toggle (stored in `localStorage`) and the interactive dot field in the homepage hero.

### Running locally
Install [Hugo extended](https://gohugo.io/installation/) (CI uses 0.154.0) and run:

```sh
hugo server -D
```

The site is then served at <http://localhost:1313> with live reload. `-D` includes draft posts.

### Publishing
Every push to `main` triggers the [Publish workflow](.github/workflows/publish.yml). It installs Hugo and runs [`publish.sh`](publish.sh), which:

1. checks out the `gh-pages` branch into `public/` as a git worktree,
2. builds the site with `hugo` into that directory,
3. commits the output and force-pushes `gh-pages`.

GitHub Pages serves the `gh-pages` branch on the custom domain from `static/CNAME`.
